# 本机性能与资源统计

这些是单台电脑的实测观测，不是跨硬件标准基准。每组数据的输入、采样方式和时间窗口不同，不将它们合并成一个“平均速度”。私人音频、字幕正文和本机路径未随统计发布。

## 配置与模型

测试日期：2026-09-16。Windows 11 Pro，版本 10.0.26200；Intel Core Ultra 5 125H，14 核 / 18 逻辑处理器；物理内存约 16 GB。运行中的原型 GUI 使用 Python 3.14，翻译 worker 使用 Python 3.11.16；独立仓库安装环境统一为 Python 3.11。CPU 推理，不使用 GPU；翻译配置 4 线程，不等于整个应用固定占用 4 个线程。

| 用途 | 模型 | 量化与运行时 | 主权重文件 |
|---|---|---|---:|
| 英语 ASR | NVIDIA Nemotron Speech Streaming EN 0.6B | Q8_0；NeMo-Speech.cpp v0.1.0 CPU | 667.45 MiB |
| 默认英译中 | 腾讯 Hy-MT2 1.8B | Q4_K_M；llama.cpp b11005 CPU，上下文 2048 | 1080.59 MiB |
| 可选英译中 | NLLB-200 distilled 600M | INT8，实际计算 int8_float32；CTranslate2 4.8.2，beam 1 | 593.75 MiB |

1 MiB = 1,048,576 字节。文件大小不等于运行内存；NLLB 还需要词表和 tokenizer，运行时还会分配计算缓冲。固定版本、来源和哈希见 `assets.json`，许可见 [THIRD_PARTY.md](../THIRD_PARTY.md)。

## 同样本离线速度

两段约两分钟课堂录音先转写，再用当时的桌面切句逻辑生成相同的 21 个英文片段，通过实际 JSONL 翻译 worker 串行处理。每个模型首请求包含加载；热运行统计剩余 20 段，记录请求的墙钟时间。

| 模型 | 热运行算术平均 | 热运行中位数 | 热运行最长 | 首请求含加载 |
|---|---:|---:|---:|---:|
| NLLB | 0.576 s/段 | 0.617 s/段 | 0.986 s/段 | 3.138 s |
| Hy-MT2 | 1.726 s/段 | 1.760 s/段 | 2.476 s/段 | 4.685 s |

该批次 NLLB 有 2 个片段触发异常保留英文，Hy-MT2 为 0；语义误译不一定触发保护，不能以异常数代替准确率。首请求时间不是纯模型加载时间，也不是每次启动承诺。

ASR 独立文件转写记录：119.98 秒音频耗时 60.918 秒，RTF = 0.508，即每秒处理约 1.970 秒音频。包含该次运行的加载与收尾。文件转写吞吐不是实时字幕延迟，且未在该轮采集内存和 CPU 数据。

## 同段系统声音回放

通过真实悬浮窗，分别从未加载翻译模型开始，将同一个 120 秒 WAV 经默认扬声器 → WASAPI → ASR → 翻译 → TXT。两次顺序运行，后台负载不完全受控。

| 指标 | NLLB | Hy-MT2 |
|---|---:|---:|
| 音频待识别峰值 | 4.40 s | 4.70 s |
| 待译峰值 | 28 词 | 31 词 |
| 最早未译文字等待峰值 | 20.26 s | 24.35 s |
| 延后补译片段 | 0 | 0 |
| 异常保留英文片段 | 3 | 0 |
| 停止后待译 / 音频积压 | 0 / 0 | 0 / 0 |

两轮均完整采集/处理 120 秒；首 30 秒后音频积压峰值约 0.1 秒。未出现持续增长趋势，但不能外推整堂课稳定性。此处等待包含切句、模型加载、排队和推理，不是逐字声学对齐的端到端延迟。

## 当前会话旁路采样

正在使用的 Hy-MT2 + 麦克风会话，保持原进程及设置，单独采样两分钟。资源从实际 GUI 及其子进程树读取，推理耗时从该窗口内新增的 llama-server timing 行提取；不保存日志原文。队列通过临时诊断观察器读取 GUI 已有计数器，每秒一次，不更改 ASR 或翻译队列。

采样前停止额外基准进程，该额外基准结果不计入此报告；后台其他用户程序未关闭。这是稳定运行窗口，不包含冷启动。资源窗口 120.77 秒、118 次采样；GUI 队列取落在相同窗口的 118 次观测，全部属于同一会话，且始终在麦克风录音 / Hy-MT2 模式。

| 延迟 / 排队指标 | 平均 | 中位数或 P95 | 最大 |
|---|---:|---:|---:|
| Hy-MT2 推理（20 次） | 1.713 s | 中位 1.731 s；P95 2.300 s | 2.966 s |
| 生成速度（每次请求的 tok/s） | 13.841 tok/s | 中位 13.755 tok/s | 17.460 tok/s |
| 最早未译文字年龄（状态采样） | 10.943 s | P95 14.870 s | 17.620 s |
| 待译词数（状态采样） | 18.898 | P95 29 | 33 |

期间字幕片段数净增 20；待译由首样本 11 词到末样本 16 词，末样本最早等待 10.73 秒。结束时录音仍在继续，因此不是“停止后的剩余积压”。延后补译片段一直为 0，识别错误与翻译异常计数没有增加。观察期间约 34.7% 样本处于翻译 busy 状态；其余等待不全是模型推理，短句触发/持续 ASR 更新也影响等待。短窗口不足以证明长时不积压。

| 进程组 | 平均工作集 RSS | 峰值工作集 RSS | 平均私有提交内存 |
|---|---:|---:|---:|
| Nemotron ASR | 647.68 MiB | 647.85 MiB | 3713.14 MiB |
| Hy-MT2 / llama-server | 1101.28 MiB | 1103.66 MiB | 1004.57 MiB |
| GUI 与 Python workers | 42.18 MiB | 42.88 MiB | 190.21 MiB |
| 整个 App 进程树 | 1791.14 MiB（1.749 GiB） | 1793.42 MiB（1.751 GiB） | 4907.92 MiB（4.793 GiB） |

进程树平均 CPU 占整机 **25.69%**，约相当于 4.62 个逻辑处理器的 CPU 时间；不是物理核占用或有效算力比例。系统可用内存最低 **0.139 GiB，约 142 MiB**，较低 RSS 与较高私有提交量应一起看，不能推导“2 GB 内存即可运行”。采样未记录页面换入换出速率，不能断言这次延迟具体有多少由分页导致。

去除私人路径、进程 ID 和日志正文的机器可读数据：[performance-data.json](performance-data.json)。

## 口径与复现

- RSS 是各进程工作集之和，可能重复计算共享页面；不是整个系统内存增长量。
- Private Commit 是私有提交内存，不等于实际驻留物理内存。采样峰值可能漏过小于一秒的瞬时尖峰。
- CPU 百分比使用进程树的 CPU 时间增量 / 墙钟时间 / 18 逻辑处理器，整机满载为 100%。它是观察期平均，不能代表仅生成时的 CPU 占用。
- 服务器 `total time` 包含 prompt 计算和生成，不包含 ASR、等待切句、GUI 排队及显示刷新；完成落在窗口内的请求可能稍早开始。
- 队列中的“最早等待”是当时最旧未译文字的年龄，不是每句完成延迟；平均值、P95 属于每秒状态采样，不能当作请求延迟分位数。
- NLLB 当前会话资源、Mac 内存/速度、冷启动资源峰值尚未采样，不用其他指标估算填表。

安装可选观察依赖 `python -m pip install -r requirements-benchmark.txt`，在项目目录运行：

```text
python scripts/observe_resources.py --pid <GUI进程ID> --log <当前Hy服务器日志路径> --seconds 120
```

该工具只读取指定进程树和日志新增部分，不控制录音，也不包含 GUI 队列探针；输出 `diagnostics/active-resources.json`。当前按 Windows 进程名分组，仅在 Windows 验证。只发布去除路径、进程 ID 和内容的汇总，不直接提交私人会话日志。
